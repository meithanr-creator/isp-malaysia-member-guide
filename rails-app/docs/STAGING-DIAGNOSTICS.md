# Restricted staging diagnostics

This increment is preparation only. Cloudflare remains stopped and the completed lease is not extended. Production ordinary logging is not enabled by this implementation.

The private staging path records at most16 detailed traces plus at most1024 admitted UUIDs for the namespace lifetime. The UUID memory is committed atomically with admission so an evicted detailed trace cannot authorize a repeated dispatch. Capacity exhaustion or malformed/inconsistent state fails closed without erasing evidence. No timestamp change resets this memory or the persisted earliest lease.

Only an exact API-key request can choose its trace UUID. Browser/client identifiers are overwritten at the edge; diagnostic headers are stripped on forwarding and both public proxy passes. Cookies alone cannot retrieve the diagnostic path. Lookup requires an exact canonical GET path and API key, checks persisted earliest expiry before and after the read, and never starts a container, arms/extends a lease, writes diagnostics, schedules an alarm or renews activity.

Fields are limited to opaque UUIDs, phase, outcome, timestamps, dispatch intent, response status and a validated exception class. Paths, queries, headers, body bytes, provider messages, credentials and member/payment fields are excluded. Rails metadata middleware observes the existing exception renderer and existing controller rescues; it neither rescues application exceptions nor changes status, cookies or body. Operation/class metadata is accepted only when Rails echoes the generated request trace. A previously observed Rails response class/status remains authoritative over a later transport update.

`dispatched=true` means durable **dispatch intent**, written before forwarding. It does not prove Rails received or committed the request. `response_received=true` means response headers were observed from Rails; its status is distinct from the generic public503. Missing, evicted, corrupt, expired or incomplete diagnostics never establish rollback or authorize replay. Always reconcile the exact database revision, attachments and audit result after an ambiguous mutation.

The hosted acceptance driver persists a UUID on drive D before sending request bytes, then performs a same-origin diagnostic GET after a qualifying failure. It releases its concurrency slot before lookup, counts lookup against the existing350-request limit, retains the ten-minute reserve, and never retries the mutation. It saves only canonical validated trace metadata; unavailable lookup stays UNKNOWN. Readiness preflight must prove actual deployed correlation and retrieval before functional mutation tests.

Admission and dispatch-intent persistence must succeed before startup/forwarding. A postresponse persistence failure does not replace an already observed successful response with503; the older durable intent remains conservative. A restricted capture must be collected within the authorized lease. There is no general public log endpoint or unrestricted collection.

Local proof: six Rails middleware tests plus a real three-controller upload integration test (seven tests/63 assertions); bounded store/concurrency/replay/privacy tests; actual proxy-path backend500 versus transport failure, fresh-instance lookup with startup/renew/write traps, key/cookie/host/expiry denials, and storage-failure checks. These source/local results do not establish hosted delivery or explain the historical503. The next candidate still requires exact CI, immutable image provenance, Astra review and an explicitly authorized new runtime window.

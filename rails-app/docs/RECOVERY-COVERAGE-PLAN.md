A fresh window needs its own sealed lease, actual provider identities, resource reservation and live independent watchdog; never reset the expired original lease. ## Failure and cleanup rules

Any uncertain mutation,503, timeout, unexpected browser failure or independent-state mismatch halts further mutations. Capture the restricted trace UUID/class/phase and exact upload operation identity, then inspect database revisions/attachments/audits/ledger and precise R2 keys. No automatic POST/batch retry. Generic503 alone does not diagnose scanner/storage or establish rollback.

Recovery is exact-operation-only. Preserve unreferenced pending/tombstone rows indefinitely unless a separately reviewed terminal-proof procedure authorizes retirement; DELETE plus absent HEAD at one instant does not prove an earlier PUT can never finish. The fixture operator correctly refuses cleanup that would erase this evidence. Do not use global unattached-blob purge, database reset, broad bucket delete or fixture-policy bypass.

Stop compute even if data cleanup remains blocked. Retain exact unresolved resource/key/row identities privately, report the failed cleanup separately and leave the affected gate open. Independently verify stopped Cloudflare instances and created Neon compute absence; record whether originals are preserved. No production readiness statement is allowed while required P2/P3 evidence or the distinct P4 owner decisions remain unresolved.
